## Product boundary

3D Core is a small, browser-first 2D/3D editor for civil, mechanical, and asset-placement workflows. The first release must run from one codebase on Windows, Linux, macOS, Android tablets, iPadOS, and WebAssembly-capable web browsers. It is **not** a fork of Blender, Cycles, Chili3D, or Pascal Editor. Those projects are design references only; their code and full native runtime are not copied into this product.

## Reference-informed design

| Reference | Adopted principle | 3D Core decision |
| --- | --- | --- |
| Blender | Familiar viewport, object tools, outliner, inspector, timeline | Keep a compact workspace and direct manipulation; do not embed Blender or require Python add-ons. |
| Cycles | Renderer is a replaceable service with progressive quality settings | Use WebGL renderer now; add optional WebGPU/local render adapters later. Do not promise Cycles GPU rendering in the web client. |
| Chili3D | Document + command + storage + viewport adapters | Keep scene state, commands, rendering, persistence, and optional CAD kernel as separate layers. Add OCCT/WASM only behind a lazy-loaded adapter. |
| Pascal Editor | Flat node registry, tool state, plugin registry, local-first persistence | Store a small serializable scene graph and undo stack locally. Plugins are optional and isolated. |

## Target architecture

```text
web/ (HTML, CSS, JS, WebGL/WebGPU)
  -> document model + commands + undo/redo
  -> render adapter (WebGL now, WebGPU optional)
  -> persistence adapter (IndexedDB/browser download)
  -> optional feature adapters (CAD/WASM, AI, remote renderer)

server.py
  -> dependency-free static host + local asset catalog APIs
```

The server is optional for a hosted build but useful for local assets. No core editing action may depend on cloud access. Heavy assets and optional WASM kernels must load only when the user invokes the related feature.

## Delivery phases

### Phase 0 — Portable baseline (complete)

- One dependency-free Python local server, configurable through `PORT` and `THREED_CORE_HOST`.
- Browser workspace with WebGL viewport, selection, transforms, primitives, basic materials, animation controls, and local asset catalogs.
- Windows launcher: `scripts/run.ps1`; macOS/Linux launcher: `scripts/run.sh`.
- Compact touch layout for tablets and phones.
- **Dockable panel layout — real, tested:** every major panel (SketchUp tool palette, Outliner+Properties, Timeline, AI Assistant) has a drag handle (`⠿` header). Drag it near a screen edge to dock there (viewport reflows around it via normal flexbox, no manual layout math), or drop it anywhere else to float freely with a native CSS resize handle. Layout persists across reloads via `localStorage`; Window ▸ Reset Layout clears it back to the built-in default. Caught one real bug while building this: calling `setPointerCapture()` *before* reparenting a dragged element into its floating layer silently kills the capture (and therefore the whole drag) the moment the reparent happens — the fix is reordering so the reparent happens first.

### Phase 1 — Real document core (complete)

- JSON scene schema: nodes, transforms, materials, metadata, hierarchy — `sceneToJSON()`/`loadSceneFromJSON()` in `web/js/app.js`, built on `THREE.Object3D.toJSON()`/`ObjectLoader` rather than a hand-rolled format.
- Command history with undo/redo (`pushUndo`/`undo`/`redo`) covering add, delete, duplicate, transform-gizmo drag, material edits, and GLB import.
- Save/open using IndexedDB (File ▸ Quick Save/Quick Load) and `.3dcore.json` file download/upload (File ▸ Save Project/Open Project).
- Debounced autosave to IndexedDB on every undo-tracked change, with auto-restore on page load — refreshing the browser no longer discards in-progress work.
- Deterministic GLB import/export in the browser (File ▸ Import/Export GLB) via `THREE.GLTFLoader`/`GLTFExporter` — real binary round-trip, not a server stub.

### Phase 2 — CAD essentials (tool suite complete; sketch/CAD primitives still open)

**SketchUp CAD tab — real, tested:**
- Line (click to add points, double-click/Enter to finish, Esc to cancel), Rectangle and Circle (drag, produce real extrudable mesh faces), 2-Point Arc (3-click: start/end/bulge), Tape Measure (real distance, leaves a persistent dashed Guide object), Eraser (deletes the clicked object). All raycast onto an existing face if you're hovering one, else the ground plane. Full undo/redo.

**Modeling tab — real, tested, all reachable from a "Mesh Edit Tools" panel that didn't exist before (most of these had no button wired to them at all):**
- Face/Vertex/Edge select: all three raycast-picked and highlighted (Face: multi-select via Shift+click; Vertex/Edge: picks the nearest vertex/edge of the clicked triangle, grouping every position-array duplicate at that world coordinate so a shared corner moves as one).
- Extrude Region, Extrude Along Normals (per-vertex-normal variant), Inset Faces, Shrink/Fatten, To Sphere: real per-vertex geometry edits with real side-wall stitching where applicable.
- Bevel: approximated as extrude-a-little + inset-the-cap (real geometry change, not a true half-edge chamfer).
- Spin: revolves the last-drawn Line/Arc profile around the Z axis into a real lathed solid (`THREE.LatheGeometry`) — ties the sketch tools into the modeling tools.
- Vertex Slide / Edge Slide: drag a selected vertex/edge; it snaps to the closest point along whichever adjacent edge best matches the drag, found via real adjacency (not a half-edge structure — a lighter position-grouping approach that's sufficient for single-element sliding).
- Bisect: drag a line across the viewport; it defines a cut plane (appears as that straight line from the current view, matching Blender's Bisect gizmo) and clips every triangle it crosses via Sutherland-Hodgman polygon clipping, keeping both halves.
- Knife: Face-select a face, arm Knife, click two points on it — cuts a straight line between them, scoped to the selected patch (not a free-form path across the whole mesh).
- Loop Cut: scoped to a single selected quad face (the common case — one full box face) — splits it into two new quads along the midpoints of its opposite boundary edges, found by tracing the boundary loop's real connectivity.
- Poly Build: click points in the viewport (on existing geometry or empty space) to fan-triangulate a brand-new face, double-click/Enter to finish.
- Smooth: real Laplacian smoothing — pulls each selected vertex toward the average of its real adjacent vertices.
- Randomize: jitters each selected vertex along its own normal by a random amount.
- Extrude Individual: like Extrude Region, but each selected face gets its own independent cap and side walls (runs the extrude engine once per face instead of once for the whole patch).
- Extrude to Cursor: extrudes the selected face along its normal by however far a single viewport click lands along that normal.
- All of the above fall back to the old whole-object scale approximation (still undo-tracked) when nothing relevant is selected, and are undo/redo-tracked either way.

**Object Mode select tools — real, tested:** Select Box and Select Circle (drag a rectangle/circle over an object) — every button/tool `idname` in the Modeling and Object toolbars was cross-checked against Blender's own `space_toolsystem_toolbar.py` (in `reference/`) for exact naming. Scoped to this app's single-selection model (picks whichever object's screen position is closest to the drag region's center among those inside it) rather than true multi-select, since the whole inspector/material/delete/duplicate pipeline here is built around one `selectedObject` — extending that to multi-select would be a separate architecture change.

**Additional Edit Mode tools — real, tested** (gaps found by cross-checking ZEPETO Studio's Blender-based modeling guides at `docs.zepeto.me/studio-guide/modeling-basics` and `modeling-applications` against what this app already had):
- Delete/Dissolve (X): previously X always deleted the *whole object*, even with a face/vertex/edge selected in Edit Mode. Now deletes just the selected face, or every triangle touching the selected vertex/edge.
- Merge by Distance (M): welds any vertices within a small threshold across the whole mesh to their average position — Blender's most-used Merge variant; doesn't need a multi-vertex-selection UI (this app's Vertex select is single-element), and is exactly what's needed to close tiny numerical gaps left by Bisect/Knife.
- Shade Smooth / Shade Flat: a real, explicit action in Blender too (doesn't survive topology edits automatically there either) — matters here because `ensureNonIndexed()` duplicates every vertex the first time any edit tool touches a mesh, so originally-smooth primitives (UV Sphere, Cylinder, Cone) would otherwise look faceted everywhere after a single edit, not just at the edited spot. Shade Smooth re-averages normals across every group of vertices still sharing a world position.
- Recalculate Normals (Outside) / Flip Normals: flips any triangle whose winding points toward the mesh's own centroid instead of away from it (the standard heuristic); Flip reverses the selected face(s), or the whole mesh if none selected.
- Face Orientation viewport overlay: translucent blue = outward-facing, red = inward/flipped, rendered as live children of each mesh so it tracks transforms (toggle off/on to refresh after a geometry edit).
- Statistics: live triangle/vertex count now shown in the viewport HUD.

**Sculpting tab — rebuilt from Blender source, real and distinct per brush (see 2026-08 entry below for the full rewrite; this line kept for section continuity).**

**Still open:** grid inference/snapping, dimension annotations, DXF parser with file-existence/type validation (no static fallback geometry presented as parsed input), optional lazy-loaded OCCT/WASM adapter for STEP/IGES/boolean operations. Bisect/Knife/Loop Cut are scoped simplifications (single cut plane / selected-patch-only / single-quad-only respectively) rather than Blender's full arbitrary-topology versions, which would need a proper half-edge mesh structure this app doesn't have. Cross-checking against `space_toolsystem_toolbar.py` also surfaced tools intentionally left out as lower-value or out of scope for a lightweight CAD app: Rip Region/Rip Edge, Extrude Manifold (approximated by Extrude Region), Offset Edge Loop Cut, Select Lasso, Scale Cage/Shear/Bend, and the sculpt-mode box/lasso/line mask-and-trim gizmo tools (a whole separate masking subsystem) — plus entire Blender editors this app doesn't have a use for (Grease Pencil, Node Editor, Sequencer, Weight/Texture Paint). The ZEPETO guides also named Loop Selection (Alt+click an edge ring), Fill (F, close a boundary loop with a new face), Proportional Editing (O, falloff-based transform of nearby vertices), Mark Sharp, Normal Maps, and Pose Mode — all still open; Pose Mode specifically needs a skeleton/armature system this app doesn't have at all.

**Bugs found and fixed while building the above** (silent correctness bugs, not just missing features): (1) this three.js build's `BufferGeometry.clone()`/`BufferAttribute.clone()` reuses the same underlying `Float32Array` instead of copying it, which was silently corrupting every geometry-edit undo snapshot (extrude, inset, bevel, sculpt, duplicate) the moment a later in-place mutation touched the "before" state — fixed with a `deepCloneGeometry()` helper that actually copies the arrays. (2) plain object-click-selection was still active during Sculpt Mode, so releasing the mouse after a stroke could silently reselect a different, overlapping object out from under the sculpt target. (3) plain sub-element-select (face/vertex/edge toggle) was still active while Vertex Slide/Edge Slide/Bisect/Knife were armed, so a click meant to place a cut point or start a slide could also toggle a selection out from under the tool.

### Phase 3 — Rendering and performance

- WebGL baseline with adaptive pixel ratio and low/medium/high quality presets.
- Capability detection: WebGL2 required, WebGPU enhancement optional.
- Optional remote/off-device renderer with explicit consent and job status; never claim P2P/GPU execution until it is implemented.

### Phase 4 — Assisted assets (AI Assistant started)

- **AI Assistant — real, tested (with a mocked provider response; needs a user-supplied API key to hit a real provider):** a natural-language command panel (AI ▸ AI Assistant) that sends the prompt plus a scene summary to `/api/ai-command`. `server.py` relays it to whichever provider is configured (AI ▸ AI Settings — Anthropic or OpenAI, both via plain `urllib`, no SDK dependency) with a curated tool schema (`add_primitive`, `set_transform`, `apply_material`, `mesh_edit`, `select_object`, `delete_selected`, `duplicate_selected`, `set_shading_mode`, `new_scene`). Whatever tool calls come back are executed through `executeAIAction()` in `web/js/app.js` — a fixed dispatch table onto the app's real functions, so the AI can only ever invoke one of these named, validated operations, never arbitrary code, and every action goes through the normal `pushUndo` system exactly like a manual click (verified: 3 chained AI actions — add cube, apply gold material, move to x=2 — all landed with exact values and all 3 undid cleanly).
  - The API key is entered once in AI Settings, saved to a local `ai_config.json` next to `server.py` (gitignored, never re-sent to the browser after saving — GET only reports whether a key is configured), and used only in the direct HTTPS call to the provider you picked.
  - Verified end-to-end against the *real* Anthropic API (with a placeholder key) — server correctly builds the HTTPS request and returns Anthropic's real 401 error cleanly, proving the network path works; a valid key is needed to get real tool calls back.
  - Tool surface is intentionally a curated starting set — grows one tool at a time, same incremental approach as the rest of this app's tool coverage.
- Offline asset metadata and local deletion.
- Generated-asset provenance tracking for AI-created geometry — not yet done (current tool calls create normal, unlabeled scene objects).

### Phase 5 — Platform release gates

- Browser matrix: Chromium, Firefox, Safari; touch matrix: Android Chrome and iPadOS Safari.
- Desktop wrappers only if required: Tauri for Windows/Linux/macOS using the same web bundle; no separate renderer implementation.
- PWA manifest/service worker for installable tablet use after offline asset caching is verified.
- CI checks: JS syntax/lint, Python compile, API contracts, scene round-trip, and a browser smoke test.

### Cross-cutting UI audit — decorative-looking elements made real

A pass specifically hunting for controls that *looked* interactive (cursor:pointer, a plausible-sounding label) but had no handler wired up at all:

- **Properties panel accordions** — all 13 section headers (`▼`/`▶`) had `cursor:pointer` and zero click handlers; every section was permanently expanded and the two empty ones (Delta Transform, Relations & Visibility) had no content at all. Now: a real `toggleAccordion()` collapses/expands each one, and the two empty sections got real content — Delta Transform (an offset layered on top of the object's normal Location, undo-tracked, Reset Delta to clear it) and Relations & Visibility (Show in Viewport / Selectable checkboxes wired to `mesh.visible` and a custom `userData.selectable` flag the raycaster now actually respects).
- **Outliner eye icon** — was static `👁 🖥 📷` text with no click handler; now the eye icon really toggles `mesh.visible` (which also makes three.js's raycaster skip it automatically), dims the row, and deselects if you hide the selected object.
- **Timeline menus** (Playback/Keying/View/Marker) — were plain `<div>` labels, not even styled as buttons; now real dropdowns (Play/Pause, jump to start/end; Insert/Delete Keyframe; Frame Selected/Frame All; a real Marker system — Add/Clear/jump prev-next, drawn as green ticks on the dope sheet).
- **Help menu** — had no dropdown and no `onclick` at all; now opens a real modal with a full keyboard-shortcut reference and an About panel.
- **Offset tool** — the toolbar button armed `activeTool = 'offset'` but no pointer handler anywhere ever read that state, so dragging on the canvas did nothing. Now works like SketchUp's real tool: click any face on the selected mesh (no separate face-select step needed) and drag to live-preview inset/outset, release to commit — reuses the same real `insetSelectedFaces()` engine as the Inset Faces button.
- **Keyboard shortcuts** — most toolbar tooltips advertised a hotkey (Eraser "E", Tape "T", Push/Pull "P/U", Offset "F", Paint "B", Rotate "Q/R", Line/Circle/Arc "L/C/A") that was never actually bound; only G/R/S worked. Filled in every non-conflicting one; kept R as Rotate only (SketchUp's own "Rectangle (R)" claim was the actual conflict, so that tooltip was corrected instead of shadowing Rotate) and made L/C/A/M context-sensitive (SketchUp-tool bindings only while that workspace is active; M does Merge by Distance in Edit Mode, Move tool elsewhere) so nothing Blender-standard got clobbered.
- **Navigation gizmo** — only 3 of 6 axis-aligned views were reachable (Right/Front/Top); added Left/Back/Bottom (hollow rings + a Bottom-view button + Ctrl+Numpad1/3/7), all routing through `setViewAngle()`.
- Verified Orbit (middle-drag) and Pan (right-drag) still function correctly — unaffected by all of the above.

**Two real bugs caught while doing this pass** (both silent, not just missing features): (1) `.dock-rail`/`.dockable-panel`'s `overflow:hidden` — added for the dockable-panel system — was clipping any popup launched from inside a docked panel, which silently broke every Timeline dropdown; fixed by making the rail/panel shells `overflow:visible` and keeping the actual scroll-clipping on `.dock-panel-body` only (with the Timeline's body specifically set to `visible` too, since it's a single-row toolbar, not a scrolling list). (2) `<canvas>` isn't natively focusable, so clicking the 3D viewport doesn't reliably blur a previously-focused `<input>`/`<select>` — since `setupKeyboard()` ignores all keydown events while an input has focus, this silently disabled every keyboard shortcut after using any input field, with no visible symptom until you tried a hotkey. Fixed by explicitly blurring `document.activeElement` on canvas pointerdown.

### Interaction feel + real Constructive Solid Geometry + a small BIM toolset

A second pass addressing "I can't tell what's selected, docking only resizes one way, tools have no feel" plus a genuinely large feature addition (real boolean CSG, and Wall/Slab/Window-Door tools built on it):

**Interaction feel — real, tested:**
- **Selection outline** — previously the *only* way to tell something was selected was the highlighted row in the Outliner; nothing showed in the 3D viewport itself. Added a real orange selection highlight (inverted-hull technique: a backface-only shell offset a constant distance along each vertex normal — deliberately a constant offset, not a uniform scale, since a uniform scale looks fine on cube-ish objects but balloons badly on thin ones like a 0.2m wall).
- **Select Box / Select Circle** now draw a live translucent rectangle/circle overlay while dragging (previously the drag was invisible — the selection happened but you saw nothing until it was over).
- **Per-tool cursor feedback** — every tool now sets a real `canvas.style.cursor` (crosshair for draw tools, not-allowed for Eraser, resize cursors for slide/push-pull, etc.); previously every tool used the same default arrow.
- **Right-click context menu** — previously did nothing. Now: Add [primitive] at the exact clicked point (raycast onto existing geometry or the ground plane), plus Duplicate/Delete Selected. Guards against OrbitControls' right-drag Pan so panning the camera doesn't pop the menu open.
- **Dockable panel resize** — docked panels only had a fixed size with no handle at all; added a real drag handle on the inner edge (native CSS `resize` already covered floating panels), persisted in the saved layout.
- **Units** — a real app-wide unit setting (m/cm/mm/ft/in), always visible next to the VCB measurement box (not buried in a menu), applied to Tape Measure/Rectangle/Circle/Push-Pull display.
- **Tape Measure dimension decorations** — was a plain dashed line with distance only in the tiny VCB text; now real perpendicular end-ticks, inward arrowheads, and a canvas-texture text label at the midpoint, matching an actual dimension line.

**Real Constructive Solid Geometry (Boolean Union/Subtract/Intersect + Hollow) — new, tested:** a full BSP-tree CSG implementation (the standard technique — same approach as Evan Wallace's csg.js), wired to Modeling ▸ Boolean buttons that previously didn't exist at all (the UNION/INTERSECT/DIFF cases in the code were dead — no button ever called them). Select object A, click a Boolean button, click object B; the operation bakes both into world space and replaces A's geometry with the real result, B is removed, fully undo-tracked. Hollow/Shell does a real subtract of an inward-scaled copy of the object from itself. Verified with exact geometry math: two known 2×2×2 cubes overlapping by 1 unit — Union/Subtract/Intersect bounds all landed exactly on the hand-computed cut planes.

**BIM toolset built on the CSG engine — new, tested:**
- **Wall** — click points to draw a continuous path (live thickness/height settings panel appears next to the toolbar the moment the tool is selected), double-click/Enter to finish; produces one real merged mesh (not a Group of separate boxes), so it's a normal selectable/booleanable/editable object.
- **Slab** — click 3+ corners, produces a real extruded flat polygon (top + bottom + side walls, fan-triangulated).
- **Window/Door Opening** — click a wall, and it one-click-cuts a real opening using the CSG engine (width/height/sill-height from the settings panel — sill=0 for a door, >0 for a window).
- **Door/window presets** — Save as Preset stores the current width/height/sill under a name (localStorage); the preset dropdown re-applies it instantly next time, so common door/window sizes are one click instead of re-typing dimensions each time.

**Two real, subtle bugs found and fixed while building the above** (this was the hard part of this pass): (1) the Wall/Slab merge helper (`mergeMeshesToGeometry`) read a `BoxGeometry`'s `position` attribute directly and treated sequential triples as triangles — but `BoxGeometry` is *indexed* (24 shared vertices + a 36-entry index defining the real 12 triangles), so skipping the index produced completely wrong triangle topology. This silently broke raycasting against every wall (0 hits, even dead center) and fed garbage into the CSG engine. Fixed by expanding to non-indexed first, exactly like `ensureNonIndexed()` already does elsewhere. (2) The Opening tool's cutter box used the wall's overall bounding *diagonal* (its length) as the cut depth instead of its extent specifically *along the cut direction* (its thickness) — a wall 5m long and 0.2m thick got a cutter 6m deep, and that 30x size mismatch triggered real numerical error in the BSP split where the oversized cutter's own far boundary leaked into the subtract result instead of being cleanly clipped away. Fixed by measuring the target's actual extent along the cut normal and sizing the cutter proportionately (a small margin over the real thickness, not an arbitrary multiple of the whole object). Both were caught by exact-geometry verification (raycasting through where a cut opening should be, and checking result bounds against hand-computed expectations) rather than "it didn't crash" — the same standard applied throughout this project.

### Wall corner-fill, robust selection outline, and hover inference/axis guides

Third pass, fixing two bugs the user hit live (screenshot-reported) plus building the first item of the "detection feel" feature list:

- **Wall corner-gap bug (fixed)** — `finishWall()` built each path segment as an independent box spanning exactly point-to-point; at a corner where the path turns, neither adjoining box extends into the other's footprint, leaving a wedge-shaped gap between their outer/inner edges (the user's screenshot showed this as an incompletely-filled corner). Fixed by extending each endpoint that's shared with a neighboring segment outward by half the wall thickness along that segment's own direction, so adjoining segments overlap through the corner. Verified geometrically, not visually: raycast straight down through 4 points inside the exact wedge region of a drawn L-shaped wall's outer corner — all 4 now hit real geometry (previously they'd have missed).
- **Selection outline rendering as a solid fill on thin geometry (fixed)** — the backface-shell-with-normal-offset technique looked fine on simple primitives but rendered as a solid orange fill on thin walls with several close-together window cutouts (visible in the same screenshot — the pillars between openings on "Wall.001"). Replaced with a real edge highlight: `THREE.EdgesGeometry` (silhouette + hard edges above a 20° threshold) rendered as `THREE.LineSegments`, which sits exactly on the real geometry with no offset and can't balloon regardless of how thin the surface is.
- **Two regressions caught and fixed while building the edge-highlight replacement** (found via the project's usual exact-value verification, not visual inspection): (1) `THREE.Raycaster` hit-tests `LineSegments` against a large default 1-unit threshold and returns a hit with no `.face` — since the outline was parented as a *child* of the selected mesh, every recursive raycast elsewhere in the app (draw-tool point picking, eraser, offset tool, opening-cutout placement) started picking up the outline itself as a spurious, faceless "closest hit" in front of the real surface, breaking raycasting against any selected object. Fixed by giving the outline mesh a no-op `.raycast`. (2) Because it was a child of the data object, `mesh.toJSON()` (used by Save Project) and `GLTFExporter` (Export GLB) both walk `children` unconditionally with no "skip me" flag — the outline was getting permanently baked into every save/export, and for `EdgesGeometry` specifically `THREE.ObjectLoader` has no deserializer at all, so reloading a saved project logged `Unsupported geometry type "EdgesGeometry"` and left a broken orphan object in the scene. Fixed by moving the outline out of the data graph entirely — it now lives as a scene-root sibling with its transform synced to the selected object's `matrixWorld` every frame, instead of being a real child.
- **Hover "detection feel" + AutoCAD-style axis-colored inference guides (new)** — every draw tool (Line, Rectangle, Circle, Arc, Wall, Slab, Opening, Poly Build, Tape) shares one chokepoint, `sketchPointFromEvent()`, so the inference logic was added there once rather than per-tool. Hovering the triangle under the cursor now snaps the point onto its nearest vertex (yellow marker, "On Vertex") or edge-midpoint (cyan marker, "On Edge") within a 14px screen-space tolerance, matching SketchUp's point-inference; and when the cursor is within ~3.4° of a pure X/Y/Z direction from the last placed sketch point, the point snaps exactly onto that axis and a red/green/blue guide line is drawn between them (AutoCAD-style). A floating tooltip follows the cursor showing the current inference label. Guides are cleared on tool switch/Escape via the existing `cancelSketchTool()` path.

## Current truth

Document persistence (scene save/open, undo/redo, GLB import/export, autosave), image-texture upload, all six SketchUp CAD drawing tools, Select Box/Select Circle, the entire Modeling edit-tool set (Face/Vertex/Edge select, Extrude, Extrude Along Normals, Extrude Individual, Extrude to Cursor, Inset, Bevel, Shrink/Fatten, To Sphere, Spin, Smooth, Randomize, Vertex Slide, Edge Slide, Bisect, Knife, Loop Cut, Poly Build, Delete/Dissolve, Merge by Distance, Shade Smooth/Flat, Recalculate/Flip Normals, Face Orientation overlay), real vertex-displacement Sculpting, the AI Assistant (natural language → real tool calls via a user-supplied Anthropic or OpenAI API key), real BSP-tree CSG (Boolean Union/Subtract/Intersect, Hollow/Shell), the Wall/Slab/Window-Door-Opening BIM toolset with saveable door/window presets and a real mitered corner join, a real edge-based viewport selection outline (immune to raycast/serialization pollution), hover vertex/edge inference and AutoCAD-style axis-colored snap guides on every draw tool, live Select Box/Circle drag previews, per-tool cursors, a right-click Add/Duplicate/Delete context menu, resizable docked panels, a real units system, and dimension-line decorations on Tape Measure are all real and run entirely client-side — verified with a scripted Playwright pass against the running app, including exact geometry-array comparisons (not just object/triangle counts) for undo/redo correctness, and — for the AI Assistant specifically — a real HTTPS round-trip to Anthropic's actual API. Bisect/Knife/Loop Cut are intentionally scoped-down (whole-mesh plane cut / selected-face-only cut / single-quad-only split) rather than Blender's unrestricted versions — see Phase 2 for what that means in practice. `server.py`'s `/api/gpu-render`, `/api/boolean`, `/api/snap`, and `/api/extrude` endpoints are unused by the current UI and still return demo responses — they must stay labelled as prototype operations until their corresponding phases are completed, or be removed if a phase decides not to route through them. (`/api/ai-generate` and `/api/export` are now superseded by the real AI Assistant and Export GLB respectively, and could be removed.)

**Opening tool auto-direction (verified, no bug found)** — re-tested against a wall drawn at a non-axis-aligned angle (~29.5°), clicked from both the front and back face. In both cases the cutter derives its orientation directly from the actual clicked face's world normal (not an assumption about which way the wall "should" face), and the resulting cut was verified as a genuine through-hole by raycasting through the opening center from both sides and confirming zero hits (i.e. nothing left blocking the doorway) rather than just checking the triangle count went up. Already correct; no code change needed.

**AutoCAD-style ViewCube (new, tested)** — replaced the old flat colored-dot ring with a real 3D cube, rendered into its own small `THREE.OrthographicCamera`/scene (`initViewCube()`/`renderViewCube()`) layered over a flat compass ring lying in the ground plane, matching AutoCAD/Blender's actual widget instead of a schematic dot layout. The cube's view-facing orientation always mirrors the main camera's current direction (the widget's own camera orbits the cube in lockstep, the cube itself never rotates), and clicking a face raycasts against it, maps the hit `materialIndex` back to a view name, and calls the existing `setViewAngle()` — so it drives the exact same camera code the old dot ring did.
